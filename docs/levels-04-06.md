# 第四至第六关：规则与场景契约

2026-09-09。用户已确认本方案并授权实施，保留前三关；允许参考截图调整样式和按钮位置。当前实施状态见 [开发计划](development-plan.md)。本文记录新关规则，不能替代浏览器和玩家验收。

## 设计原则

- 《纪念碑谷》为主要参考：改变建筑关系、主动发现错觉连接、机关具有多种用途。参考 [官方介绍](https://ustwogames.co.uk/our-games/monument-valley/) 与 [Ken Wong 的 GDC 分享摘要](https://www.gdcvault.com/play/1020878/Designing-Monument-Valley-Less-Game)。后者强调审美体验，本项目根据玩家反馈额外增加规划要求。
- 辅助参考 [无限回廊](https://blog.playstation.com/2008/04/30/echochrome-arrives-tomorrow/) 的空间连接，以及 [COCOON](https://www.cocoongame.com/) 的对象用途转换。以下具体地图为本项目原创，不声称复刻原作内部实现。
- 每关分别引入联动关系、石偶的多重用途、锁定与搭乘之间的资源取舍。没有倒计时、随机密码、死亡或消耗品；不通过拖慢角色凑时长。
- 新关默认文字只交代操作与当前状态；解法通过「查看提示」逐级提供。首次体验目标分别为 5–8、7–10、10–15 分钟，尚需玩家验证。
- 保留原前三关的规则和引导。新章使用灰紫、浅粉石材与青色机关；控件放在画布之外的底部操作区。相机按建筑边界及实际可用画布取景。

## 第四关：双环庭院

### 地图与机关

两座径向石桥围绕同一中央台 H 旋转，金色内圈和青色外圈表示各自的传动机构。窄金属圈是承重和传动构件，不是可步行的石路。四个方向分别为东 0、北 1、西 2、南 3，每格 90°。

- 内环 `inner` 与外环 `outer` 均取 0–3；初始 `(0,0)`。
- 主轮位于 S/H：外环加一格，内环减一格，模 4。
- 校准把手位于西侧 W：仅内环加一格。
- 角色只能在固定控制台操作，不能站在转桥上转动机关。

节点及坐标以 `src/advanced-levels.js` 为执行数据。中心 H=(0,0,0)；四个中间落脚点 M0–M3 半径 3.2；外侧落脚点半径 6.6。内桥路径节点 I 半径 2.6，外桥 O 半径 5，均随对应机关转动。

| 连通关系 | 条件 |
| --- | --- |
| S–B0、B1–E | 固定 |
| H–I–M(inner) | 内桥到位 |
| M(outer)–O–对应外侧落脚点 | 外桥到位 |
| W–D–F–V–Q | 固定下层楼梯和回廊 |
| Q≈I | 仅 inner=0 |

西侧外落脚点为 W；北侧 B1 接光门；南侧 B3 是可返回的观察台。Q=(-0.8,-3.4,-3.4)，I 在朝东时为 (2.6,0,0)，差为 (3.4,3.4,3.4)，平行于固定正交视线。近远切换使用遮挡柱，Q/I 不是独立停靠点。

### 标准流程

S→H；主轮两次至 `(2,2)`；走到 W；校准内环两次至 `(2,0)`；沿下层 D/F/V 通过 Q≈I 返回 H；主轮三次至 `(1,1)`；穿过两桥与 B1 到 E。

七次机关动作不是难度指标；核心是主轮始终保持 `(outer+inner) mod 4`，单纯试遍主轮无法从初始关系得到出口所需关系。W 校准后出现不同的返回路径。允许多种折返和非最短解。

错误恢复：W 的独立把手始终可调回内环，所有中间台可以回到当前相接的控制区域。必须枚举全部合法停靠状态，不能把重置计入恢复路径。

## 第五关：借身之塔

### 石偶与路线

石偶沿东西轨道逐站移动，顶部高度 y=3；可压板、供主角登乘并载人。方向名称按场景世界坐标表达，拓扑与已确认提案相同。

| dock | 石偶顶部坐标 | 作用 |
| --- | --- | --- |
| 0 | (6,3,0) | 东侧入口压板，开启 A–B |
| 1 | (2,3,0) | 中央接驳位，连接 J–P |
| 2 | (-2,3,0) | 对岸接驳位，连接 P–W |
| 3 | (-6,3,0) | 西侧出口压板，开启 Z–E |

主角停稳在 S/A/C/J/P 时可以移动石偶；W 的把手仅展开折梯。角色在 P 时与石偶同步平移。入口和出口压板没有上层落脚岸，不能从石偶顶部直接跨到其旁边的其他楼层。

固定路线：S–A，B–T–C–J，W–K–Z。T–C、W–K 是台阶。`unfolded=true` 后增加 C–V–U–L–W，形成独立回路；L 为侧向接驳点，避免楼梯压住石偶的上下客路线。折梯一经展开保持开放，整关重置才恢复收起。

### 标准流程

初始石偶在 0；从 S 通过入口门与楼梯到 C；石偶向西至 1；从 J 登上 P；向西至 2；下到 W；展开折梯；沿 L/U/V 回 C；石偶向西至 3；沿折梯去 W，再由 K/Z 穿门到 E。

必要性：未展开折梯时，石偶守出口与角色跨越深井不能同时成立。W 无远程运送把手；旅人若登上石偶再送往出口压板，会留在没有上层落脚岸的石偶顶部，可原路返回，但不能跳关。

错误恢复：两端压板上的搭乘者可以反向返回接驳位；入口控制台可以召回石偶；对岸始终可以展开折梯。门只随石偶到位提交状态，动画中不能穿门、跨台或叠加动作。

## 第六关：归光天穹

### 锁定关系

延续双环规则；入口 S 直接接中央 H。内桥与 H 之间有一段明确缺口，石偶停在中央且内环朝北时，顶部补上 H–P–I。外桥与各方向落脚台仍按实际朝向连接。

- 初始 `outer=0, inner=0, dock=0`。
- 中央石偶 P=(0,0,-1.6)；对岸 P=(-5,0,-1.6)，连接固定观星台 W=(-5,0,-3.6)。
- `dock=1` 时石偶压住锁定板，内环不能转；W 把手只转外环。
- `dock=0` 时 W/H 把手都会联动两环。
- 内环锁定时，H 主轮不能强行转动；需去 W 使用外环把手。这个位置约束防止在中央远程按完全部操作跳过搭乘。
- H/W/P 均可操作石偶往返，以保证错误状态能够恢复。石偶离开压板后只解除锁定，不自动复原环角度。
- 角色在石偶顶部不能转桥，需要先下到固定台。

### 标准流程

S→H；联动三次至 `(3,1)`；登上中央石偶；驶向观星台并下到 W；转动外环两次至 `(1,1)`；重新登上 P 返回中央；石偶补齐缺口，沿内外桥与 B1 抵达 E。

必要关系：初始仅联动不能得到目标关系；对齐两桥但把石偶留在锁板上仍有中央缺口；未下石偶不能操作外环。允许玩家在对岸召回/送走石偶重新校准，额外操作不会造成永久卡死。

## 共同技术与验收

- 新关规则位于 `advanced-levels.js`，场景位于 `level-advanced.js`，沿用共享 Game 和 Three.js，不新增依赖。
- 状态只在动作完成时提交；旋转跨越 0/3 使用相邻的 90° 角差，不播放 270° 倒转。
- 每段新楼梯按高度差 / 0.16 向上取整生成台阶；角色与场景使用相同台阶划分。
- 使用公开 Game 操作遍历可达稳定状态。正向、逆向、错误控制点、压板门禁、搭乘、提示、重置均需覆盖。
- 浏览器必须通过真实鼠标与 DOM 控件操作；开发只读诊断可以查询投影、拾取目标和状态，不能用它直接改关卡状态通关。
- 对齐接缝要求目标视口偏差 ≤1 CSS px；还需检查角色与脚影遮挡、道路上下层净空。拓扑测试不替代这些检查。
- 按钮、提示与画布边界分离；1280×720、1920×1080、DPR 2 及较小视口检查道路点击与取景。构建与外网隔离另外验证，玩家趣味性和 Mac 继续保留边界。
