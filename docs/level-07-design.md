# 第七关：换景之庭

日期：2026-09-09。六关扩展方向已确认。本文件将第七关落实为可玩原型规格；实现和验收状态见 [开发计划](development-plan.md)。

## 体验与范围

在三个固定观景台改变观察方向，利用两种视角下不同的断口连接，从低处庭院进入中空塔，再走向高处出口。保留现有旅人、点击移动与底部操作区。建筑采用雾白薄墙、青灰悬梁和铜色观景标记，减少重复方柱。

首先交付玩法原型；正式美术深化以真实试玩为依据。本轮不实现镜面世界、折页或双角色，不将十二关全部显示成可玩。

## 节点与固定建筑

坐标为 `[x,y,z]`。所有建筑和节点世界坐标固定，改变视角不会移动人物或建筑。

| 节点 | 坐标 | 用途 |
| --- | --- | --- |
| S | [-5,0,4] | 入口观景台，可换景 |
| U | [-3,0,4] | 首段断口，仅路径内部节点 |
| V | [-1,-2,2] | 首段远端，仅路径内部节点 |
| H | [1,-2,2] | 塔前观景台，可换景 |
| J | [1,0,0] | 塔内楼梯顶端，仅路径内部节点 |
| L | [3,2,2] | 上层回廊端点，仅路径内部节点 |
| K | [3,2,-0.5] | 上层观景台，可换景 |
| N | [3,2,-2.5] | 出口前断口，仅路径内部节点 |
| O | [1,4,-0.5] | 出口远端，仅路径内部节点 |
| G | [0,4,-0.5] | 门前回廊，可以停留和返回，不可换景 |
| E | [-1,4,-0.5] | 最终光门 |

稳定可点击目标为 S/H/K/G/E。断口与楼梯也具有实际碰撞面，点击它们指向所在路段的稳定平台，防止角色停在接缝内。H–J 楼梯共 13 级，步高与人物位置计算一致。G 用于抵达光门前的停留和返回，使最后一对接缝也能双向通行；进入 E 才结束关卡。

## 两视角与道路

相机始终看向固定中心 `[0,0.7,1.5]`。A 方向偏移 `(14,14,14)`，B 方向偏移 `(-14,14,14)`；初始 A。镜头绕中心平滑旋转 90°，使用整段轨迹的共同取景范围，不随每帧建筑包围盒缩放。减少动态效果时直接呈现目标视角，短暂停止交互后提交道路状态。

固定边：S–U、V–H、H–J、L–K、K–N、O–G、G–E。

| 当前视角 | 有效错觉连接 | 可走稳定平台关系 |
| --- | --- | --- |
| A | J–L | H ↔ K；S 与出口区域分离 |
| B | U–V、N–O | S ↔ H；K ↔ G ↔ E |

U/V 和 N/O 的差向量平行 B 相机方向；J/L 差向量平行 A 相机方向。因此只在指定角度投影重合。每一对连接独立判定，不能把六个断口节点混成任意互连集合。连接处用实体薄墙遮住瞬间深度转换，往返都要检查人物和脚影；镜头旋转中所有行走与重复换景输入均不执行。

换景只允许在 idle 且节点为 S/H/K。标准过渡 1 秒，结束时一次提交 view 和新道路。reset 取消过渡，恢复入口、A 视角和初始提示。动画时切换章节则完整释放该场景。

## 标准解与错误恢复

1. S/A：出口不通。换成 B，沿对齐的悬梁走到 H。
2. H/B：上层回廊不通。换成 A，沿塔内阶梯、J–L 连接走到 K。
3. K/A：光门不通。换成 B，沿 N–O 连接抵达 E。

最少换景三次。S/H/K 观景台都能换回另一角度；G 仅可在 B 抵达，可原路返回 K。所有可达稳定状态均有通关路径，不依赖重置。返回已有路段不清除任何隐形进度，因为本关只有 view 状态。无倒计时、惩罚或随机机关。

提示分三层：先提示观察断口，再提示比较两个角度，最后给当前平台的下一步。默认文案不一次性列出全解。

## 验收用例

- 初始 A 不能直接到 H/K/E；标准解三次换景通关，三次接缝计数。
- S/H/K 分别测试错误换景后换回、返回上个平台；穷举所有稳定可达状态，全部可完成。
- 相机过渡中原状态未提交、人物位置不变、移动和重复操作被拒绝；中途重置及换关恢复正确。
- 每对接缝在有效视角下屏幕误差小于 1 CSS 像素；错误视角明显分离且不连通；双向接缝的遮挡无明显人物闪跳。
- Chrome 1440×900、Edge 1280×720、DPR 2：三个观景台与光门可鼠标点击，模型不侵入底部控件，浏览器无异常；减少动态效果时无长距离旋转。
- 共享引擎改变后重跑前六关逻辑和浏览器流程；反复换关不累计 GPU 资源。
- 构建冷启动阻止外网请求后通关、重玩；记录实际构建标识。此验证不等于 Mac 真机或免 Node 玩家包验收。
- 玩家是否能解释「换景改变了什么」、是否愿意继续，是独立待试玩结论。
