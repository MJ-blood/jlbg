# 首关详细设计：回光庭院

版本：v0.2，2026-09-08。状态：用户已确认采用并授权开发，作为实现与验收基线。

本文件是首关玩法、道路和交互规则的唯一详细定义。总体方案见 [开发方案](development-proposal.md)，实施顺序见 [开发计划](development-plan.md)。「回光庭院」是关卡工作名，用户可调整；不是正式游戏名称。

## 1. 完整关卡的定义

这是一关有开场、操作学习、位置判断、视觉错觉和结尾的小型解谜。完整指从进入到通关、重玩和异常恢复均闭合，不指达到原作单章的内容量。

玩家目标：让白色旅人从入口走到高处的光门。场景只有一座单臂旋转桥，必须使用两次：第一次把桥接向入口，走到不旋转的中央岛；第二次把桥接向出口，利用视觉错觉跨越真实深度不同的两条路。

- 预期初次体验：约 2–4 分钟，包含观察和试错，是设计目标，需试玩验证。
- 熟悉解法后的流程：约 30–60 秒，不靠加长移动距离拖时长。
- 无死亡、倒计时、消耗品或不可恢复的失败。错误操作可回退，随时可以重置。
- 需要完成两个有效的 90 度旋转和一次角色跨越视错觉接缝，才可能从初始状态通关。

## 2. 场景分区与画面

| 分区 | 构成 | 玩家看到或理解的事情 |
| --- | --- | --- |
| 入口露台 | 旅人出生点、短走廊、圆形观察标记、断口 | 点击道路行走；桥目前没有接过来 |
| 中央岛与旋转桥 | 固定圆台、金色把手、一条单臂桥 | 岛不转、桥会转；先站稳在岛上才能改变下一段路径 |
| 出口塔 | 接缝遮挡柱、抬高的回廊、门前平台和光门 | 画面相接即可通行；真实高度不同不妨碍这一特定连接 |

全景固定，入口、把手和出口在初始画面中可见。场景不跟随角色转动，不使用自由轨道相机。首次取景必须同时露出入口断口与中央安全岛，不能让装饰挡住谜题关系。

拟定美术基线：背景暖白 `#F3E9DD`、主体浅砂 `#D8C3A5`、阴面灰蓝 `#657A8D`、机关金色 `#D5A24A`、终点青绿 `#78B8A4`。颜色可在预览后微调，机关和安全点还要依靠形状标识，不能仅靠颜色区分。

素材清单限定为：1 个简化旅人、3 组建筑、1 个把手、1 处遮挡柱/门洞、1 个光门及基础界面。旅人用几何体组合，建筑用几何体生成；字体采用系统字体。首关不依赖外部模型、联网音频、完整音乐或素材采购。

## 3. 玩家逐步流程

| 步骤 | 场景状态与可操作内容 | 预期动作 | 即时反馈 |
| --- | --- | --- | --- |
| 0 开场 | 显示关卡名、目标「抵达光门」和「开始」按钮；场景已可见 | 点击开始 | 约 0.6 秒淡出标题层，旅人可操作 |
| 1 学会行走 | 旅人在 S，入口路径可走；桥为 A 状态，接向出口 | 点击 W 的地面圆标 | 旅人到达观察点；首次提示「点击金色把手转动桥梁」 |
| 2 第一次旋转 | 旅人停稳 W，把手可操作 | 点击同一个金色把手，A→B | 桥转 90 度，约 0.8 秒后连接入口；标记中央岛 |
| 3 进入中央岛 | B 状态允许入口经过桥到 H；出口暂断开 | 点击 H，沿 I→R2→R1→H 行走 | 到达固定岛，首次提示「站在圆台上，再转一次」 |
| 4 第二次旋转 | 旅人停稳 H，桥可转 | 点击把手，B→A | 桥离开入口，出口接缝在画面上对齐；提示「沿着相接的道路，走向光门」 |
| 5 错觉跨越 | A 状态下 H 至出口连通 | 点击 F、G 或光门 E | 角色沿桥到接缝，平顺地进入远处高回廊 |
| 6 通关 | 角色实际到达 E | 自动触发 | 门光增强、旅人淡出；约 1.2 秒后显示「回光庭院 · 已抵达」和「再玩一次」 |
| 7 重玩 | 通关界面显示 | 点击再玩一次 | 返回完整初始状态 S/A，显示开场；不保留路径或动画 |

重置按钮在开场后一直可见，包括移动、旋转和结束动画期间。浏览器刷新同样从开场重来；本关暂不保存跨会话进度。

## 4. 地图节点与精确连通规则

坐标系：Three.js 默认右手系，Y 向上，世界长度单位暂记作 u。下表给出地面导航点，角色脚底贴在该点；角色高度不叠加进节点坐标。坐标用于灰模起点，不是已经验证过的最终美术尺寸。

| ID | 名称/作用 | A 状态坐标 (x,y,z) | B 状态坐标 (x,y,z) | 停稳后可转桥 |
| --- | --- | --- | --- | --- |
| S | 入口出生点 | (0,0,-9) | 不变 | 否 |
| W | 入口观察点，带圆标 | (0,0,-7) | 不变 | 是 |
| I | 入口断口前沿 | (0,0,-5) | 不变 | 否 |
| H | 固定中央岛，桥的转轴中心 | (0,0,0) | 不变 | 是 |
| R1 | 旋转桥内段 | (2,0,0) | (0,0,-2) | 否 |
| R2 | 旋转桥末端/近侧接缝 | (4,0,0) | (0,0,-4) | 否 |
| Q | 远侧接缝 | (6,2,2) | 不变 | 否 |
| F | 出口回廊可见落脚点 | (8,2,2) | 不变 | 否 |
| G | 门前平台 | (9,2,2) | 不变 | 否 |
| E | 光门终点 | (10,2,2) | 不变 | 否 |

道路宽度初值 0.9u；固定中央岛半径 1.2u；旅人高度 0.65u、最大宽度约 0.28u。旋转桥只有 H 外的径向桥段旋转，中央岛、把手底座和 H 上的角色保持静止。B 状态桥端到 I 的 1u 路段用固定入口短桥面覆盖，不能出现导航可过、画面却有真实空洞的情况。

**所有导航边均为双向边：**

| 类型 | 边 | 开放条件 |
| --- | --- | --- |
| 入口固定道路 | S–W，W–I | 非旋转期间可行走 |
| 中央岛与桥内道路 | H–R1，R1–R2 | 非旋转期间可行走；坐标随桥状态变化 |
| 出口固定道路 | Q–F，F–G，G–E | 非旋转期间可行走 |
| 入口接桥 | I–R2 | 只在 B 且旋转完成时开放 |
| 视错觉接缝 | R2–Q | 只在 A 且旋转完成时开放，按特殊边处理 |

没有 S–H、I–Q、H–F 等捷径。相机中偶然重叠的其他表面不产生导航边。E 的到达触发通关，不是点击它就直接通关。

```text
初始 A： [S—W—I]      [H—R1—R2 ≈ Q—F—G—E]
旋转 B： [S—W—I—R2—R1—H]      [Q—F—G—E]
回到 A： [S—W—I]      [H—R1—R2 ≈ Q—F—G—E]

≈ 代表画面投影接合、真实空间分离的唯一特殊连接。
```

标准解法的导航序列：S→W；A→B；W→I→R2→R1→H；B→A；H→R1→R2≈Q→F→G→E。

## 5. 视错觉的具体做法与验证边界

### 5.1 为什么这组坐标可以对齐

相机方向先取从 `(14,14,14)` 看向 `(0,0,0)`，up 为 `(0,1,0)`。后续可平移整个相机和观察点来居中，保持方向不变。采用正交投影，只根据窗口尺寸调整取景范围，不改变视角。

A 状态 `Q - R2 = (2,2,2)`，与相机方向平行；所以 R2 与 Q 的屏幕 x/y 坐标重合，而真实空间距离为 `sqrt(12) ≈ 3.464u`。两侧道路沿同一 X 方向延续、宽度相同，作为同一条屏幕道路处理。B 状态不成立，也不开放此边。

本轮只做了内存中的坐标投影核对：两点归一化屏幕坐标差约为 `(0, -5.55e-17)`。这证明数学关系成立，不证明建筑遮挡、角色阴影或实际画面已经自然。

### 5.2 角色跨越，不做原地走路

- 普通边按约 1.8u/s 的速度移动；R2–Q 的屏幕长度为零，不按 3.464u 的世界长度播放步行动画。
- 路径走到接缝时，以一个独立的接缝步骤切换角色深度：保持屏幕位置，脚底从 R2 映射到 Q；反向同理。
- 两端周围放一组固定遮挡柱/门洞。切换帧中角色完整轮廓和脚影必须被遮挡，前后步行节奏连续，不做镜头切换或全屏淡出掩盖。
- 角色与简单脚影同步映射；接缝区域首版不使用会暴露跳变的动态投影阴影。
- 验收阈值：在目标视口中端点屏幕偏差不大于 1 CSS px；视觉上看不到位置跳变、身高跳变、穿模、脚影闪烁或停在原地踏步。
- 双向通过、窗口大小变化以及不同设备像素比均需验证。若遮挡方案失败，先调整几何再检查，不能用普通实体接桥替代特殊连接后宣称视错觉完成。

### 5.3 点击与遮挡

R2/Q 只作为路径内部的中转节点，不设置独立点击或停靠目标，跨越由通向对岸的完整路径触发。可停靠集合明确为 S、W、I、H、R1、F、G、E。F、G、E 以及普通道路段拥有清晰的点击代理面；装饰只在确实遮挡可见目标时阻止拾取，不允许隔着墙点击背后的路。W/H 在两种朝向中都必须可见且可点；光门自身作为 E 的目标，不能靠点击穿过门饰命中终点。

点击 R1–R2 路段统一映射到 R1，点击 Q–F 路段统一映射到 F，入口固定短桥面映射到 I；其他普通路段在允许停靠的端点中取更接近点击位置者。命中接缝遮挡区则不移动，提示点击远侧可见路面。高亮目标与实际落脚目标必须一致。

## 6. 输入、状态和异常行为

使用鼠标左键或触控板单击。首版不要求拖拽旋转、不依赖悬停才能理解操作，不劫持浏览器缩放快捷键。把手和界面按钮有效点击范围至少 44×44 CSS px；道路目标尽量至少 24 CSS px 宽。

状态最小集合：`intro`、`idle`、`moving`、`rotating`、`finishing`、`won`；另有 `bridgeOrientation=A/B`、角色所在节点和当前路径。普通移动只在一个状态中进行；动画结束才提交最终节点和机关朝向。

| 当前条件 | 输入 | 行为 |
| --- | --- | --- |
| intro | 点击开始 | 保持 intro 播放约 0.6 秒淡出，完成后进入 idle；淡出中重复点击和其他场景点击无效 |
| idle | 点击可达道路或出口 | 计算当前图上的最短路径并移动；点当前节点不动 |
| idle | 点击不可达目标 | 原地不动，目标短暂标记并显示「道路尚未接通」 |
| idle 且当前节点严格为 W/H | 点击把手 | 启动一次 A↔B；不自动寻路到控制点 |
| idle 且不在 W/H | 点击把手 | 不旋转，提示「先站到带圆标的平台上」；保持可自由退回 |
| moving | 再点道路或把手 | 不追加、不打断、不排队；重置仍可用 |
| rotating | 再点把手或道路 | 不叠加动画、不安排旋转后自动移动；重置仍可用 |
| finishing/won | 点击场景 | 不再触发路径、旋转或重复通关 |
| 开场以外任意状态 | 点击重置/再玩一次 | 取消路径和所有动画回调，恢复 S/A、初始提示及开场 |
| 任意状态 | 点击空白/装饰 | 不修改游戏状态 |

停稳 W/H 是逻辑节点条件，不能仅靠屏幕位置相近来判断。角色在移动桥、接缝、出口回廊上都不能旋转。

后台标签页暂停动画进度，返回后从暂停位置继续，避免大时间差导致跨过节点。窗口调整时保持相机方向和当前游戏状态。WebGL2 初始化失败或上下文丢失时显示明确说明与重新加载入口，不留下可操作但无画面的游戏。

## 7. 回退与防卡死说明

- 玩家在 W 上过早把 B 转回 A：只是回到初始状态，再转 B 即可。
- 玩家到 I 或停在桥上 R1 后想旋转：被拒绝，但在 B 时可以继续走到 H 或退回 W。R2/Q 不允许作为停靠目标。
- 玩家在 H 连续来回转桥：每次必须等动画完成，任一朝向都能再次切换，中央岛永远不旋转。
- 玩家已停在 F/G：只能处于 A；把手不可用，可反向经过 Q≈R2 回 H。不会在出口侧把桥转走。
- 未到 E 不能完成；必须实际移动到 E。重置不保存任何已通关标记。
- 首关不需要撤销栈、死亡复活或自动传送救援，合法状态本身必须具有解法。

## 8. 首关验收用例

以下是要执行的检查清单，不是已通过的测试记录。

| 编号 | 操作或检查 | 明确预期 |
| --- | --- | --- |
| L01 | 开始后从 S 点击 E | 不移动到出口，提示断路；状态仍为 S/A |
| L02 | S→W，转 B，再点击 H | 依次经过 I、R2、R1；最终 H/B |
| L03 | H/B 转 A，点击 E | 经过 R1、R2≈Q、F、G、E，只触发一次通关 |
| L04 | W/A→B→A，重复多次 | 不出现路径残留，仍可按 L02/L03 通关 |
| L05 | 停在 I/R1 时点把手，尝试直接选中 R2/Q | 不转；能退回 W 或前往 H；R2/Q 不能作为落脚目标 |
| L06 | 到达 F 后返回 H | 反向 Q≈R2 自然通过，回 H 后仍可转桥 |
| L07 | 移动中连续点目标、旋转中连续点把手 | 不排队、不叠加；最终结果与首次有效输入一致 |
| L08 | 移动、旋转、接缝前后、结束动画、通关界面分别重置 | 全部回 S/A/intro，无旧回调导致的跳动或误通关 |
| L09 | 改变窗口尺寸、100%/125%/150% 页面缩放、DPR 1/2 | 保持错觉连接；所有按钮可用；不把背后道路错误选中 |
| L10 | 逐帧或慢速观察正向与反向接缝 | ≤1 CSS px 的投影误差，无可见深度跳变和原地踏步 |
| L11 | 暂停到后台再返回 | 角色不瞬间跑完路径，机关不跳过稳定状态提交 |
| L12 | WebGL2 不可用/上下文丢失 | 显示可读提示或重新加载入口，不误显示可游玩 |
| L13 | 清缓存、断网，从构建产物重新启动并按标准解法玩 | 开场、全部交互、通关和重玩都完成，无外网资源依赖 |
| L14 | 遍历可停靠节点 × A/B，旋转仅限 W/H，路径内部允许经过 R2/Q | 每个从 S/A 可达的未通关状态都有通向 E 的合法路径；最少两次旋转才能通关 |

L01–L08/L14 的道路和状态逻辑可用 Node 内置测试覆盖。视觉与平台用例必须实际运行，不能用逻辑检查替代。Windows/macOS 的执行矩阵见开发方案。

## 9. 本轮设计检查与待验证项

- 已核对：两状态道路连通关系、标准 A→B→A 解法、双向回退原则；内存中的设计图枚举覆盖含中转节点的 16 个可达拓扑状态，未发现无法到达终点的状态，最少需旋转两次。该结果是设计检查，不是游戏测试通过。
- 尚未验证：真实建筑是否相互遮挡、接缝柱能否完整遮住切换帧、拾取精度、操作手感、帧率及跨浏览器表现。
- 可在实现中直接调整的参数：道路宽度、动画时长、颜色、取景留白；必须保持拓扑、相机方向与视错觉约束，并重跑受影响检查。
- 需要更新方案再确认的变化：增加第二机关、改成多关、改变标准解法或用真实实体桥替代视错觉。
