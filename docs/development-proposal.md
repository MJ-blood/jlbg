# 开发方案 v0.2：完整首关与 Windows/macOS 交付

日期：2026-09-08。用户已明确采用 v0.2 并要求开始开发；本文作为实施基线，进度和实际验证结果见开发计划。

最新调整：用户已确认第二、第三关扩展，三关现已实现并通过本机功能验证。沿用现有布局，只补必要换关与机关入口，Mac 版本与打包暂缓。新关规则见 [玩法扩展设计](gameplay-expansion.md)，状态见 [开发计划](development-plan.md)，实测见 [验证记录](validation-v0.3.md)。下文“首版不做多关”等为 v0.2 原始范围，不能用于否定用户最新扩展要求；平台要求保留为后续交付基线。

## 1. 已确认目标与本版变化

已确认：浏览器游玩、初期本地离线、至少一个完整关卡、JavaScript + Three.js + Vite 的总体方案。用户新增最终 Windows 和 macOS 都能玩，并确认有一台 Apple 芯片 Mac，可用于后续真机验证。

本版把原来的“一次转桥后到出口”扩展为同一机关的两次应用：入口接桥 → 进入固定中央岛 → 再次转桥 → 视错觉通行 → 通关及重玩。没有增加第二机关、钥匙、背包或第二关。

首关的工作名、坐标、交互、状态和逐条验收详见 [首关详细设计](level-01-design.md)。其中 10 个节点、两种桥朝向和 A→B→A 标准解法构成实施基线，不再留到开发时临时决定。

## 2. 范围与交付定义

| 项目 | 首关必须具备 | 不计作已完成的替代品 |
| --- | --- | --- |
| 内容 | 开场、行走学习、两次转桥、一次视错觉、结尾、重玩 | 只有旋转模型或无法通关的演示 |
| 机关 | 一个把手、两个相差 90 度的状态、入口与中央岛两处安全操作点 | 点一下立即跳过谜题 |
| 错觉 | 真实空间分离、画面连续、角色可双向通过 | 普通实体桥接合 |
| 交互 | 可达目标移动、不可达反馈、连点限制、动画中重置 | 只覆盖正确操作顺序 |
| 美术 | 一套完整的基础建筑、简化旅人、机关和出口标识 | 灰模直接作为最终视觉完成 |
| 运行 | Windows 与 M 系列 Mac 浏览器实际运行、构建产物断网通关 | 只在当前 Windows 开发服务中运行 |
| 玩家交付 | 两个平台离线包，运行资源及所需运行时随包提供 | 要求玩家安装 Node.js 或 npm 依赖 |

首版不做多关、完整剧情、音乐系统、跨会话存档、手机触控适配、账号后台、在线排行和关卡编辑器。首次体验时长目标为 2–4 分钟，熟悉后约 30–60 秒，需试玩校准，不以拖慢角色达标。

开发验收包和玩家包是先后两次交付，但双平台玩家运行不再写成可有可无的目标。公开网站、应用商店、自动更新和生产发布不在本次范围。

## 3. 平台支持基线

以下是推荐的首批支持范围，最终声明只覆盖实际通过的系统、浏览器和架构组合；最低版本与尚未覆盖的组合不得写成已经兼容。

| 系统/架构 | 浏览器目标 | 首批定位 | 验证资源 |
| --- | --- | --- | --- |
| Windows 11 x64 | Chrome、Edge，验收时的稳定版 | 必须交付与通过 | 当前开发电脑；还需无开发依赖环境验证玩家包 |
| macOS 14 或更新版本，arm64 | Safari、Chrome，验收时记录具体版本 | 必须交付与通过 | 用户有 M 系列 Mac，具体型号、系统和浏览器版本待核对 |
| macOS Intel x64 | Safari、Chrome | 后续扩展候选；未验证不作支持承诺 | 当前没有确认可用真机 |
| Windows ARM、旧 macOS、手机/平板 | 未设定 | 首批不列入支持范围 | 后续按需要追加 |

macOS 14 是项目建议的最低测试基线，不代表所有更新版本都已测试。若用户现有 Mac 系统不在基线内，先核对运行时与浏览器要求，再调整矩阵，不能默认要求用户升级系统。

Three.js 现有版本的 WebGLRenderer 使用 WebGL2，启动时必须实际检测；系统和浏览器名称本身不是能力证明。[Three.js 官方说明](https://threejs.org/docs/pages/WebGLRenderer.html)

Mac 需验证 Safari 的拾取、透明遮挡和资源路径、触控板单击、Retina 显示与页面缩放。Windows 上的 WebKit 自动化只能辅助查问题，不能替代 Safari/macOS 真机结论。

## 4. 游戏技术设计

### 4.1 工具与拟议文件职责

沿用当前 Three.js 0.185.1、Vite 8.2.2，不在本轮升级依赖。游戏用 JavaScript ES modules；HTML/CSS 做轻量覆盖界面。首关先不用框架、物理引擎、外部动画库或 TypeScript。

批准实施后拟创建：

| 文件/目录 | 单一职责 | 验收重点 |
| --- | --- | --- |
| `index.html` | 页面入口、基本文档信息 | 可从本地构建服务加载 |
| `src/main.js` | 装配场景、渲染循环、尺寸和可见性事件 | 暂停恢复、DPR 与渲染 |
| `src/level-01.js` | 节点数据、边条件、桥变换和几何构建 | 与首关节点表完全对应 |
| `src/game.js` | 纯道路/状态规则、寻路、角色路径和机关过渡 | 正常及非法状态转换可测试 |
| `src/input.js` | 指针命中、目标映射、按钮事件 | 不穿墙拾取，不重复提交输入 |
| `src/style.css` | 开场、提示、重置、结束层和适配 | 两系统不依赖远程字体 |
| `tests/game.test.js` | Node 内置测试，覆盖关键规则 | 不建立重复实现逻辑的测试 |
| `public/` | 后续确有需要的本地静态素材 | 没有素材时不提前创建空目录 |
| `dist/` | Vite 构建产物 | 源码以外的实际交付对象 |

分工按单关规模执行，不提前搭建通用引擎。若代码变长，只按明确职责调整文件，不把这个表当作必须照搬的架构。模块加载和节点几何以已安装源码为准。

### 4.2 导航与动画契约

- 节点和边以首关设计为唯一数据来源；普通边使用简单最短路径搜索，特殊接缝边带明确类型，路径不得跳过它。
- 稳定状态 A/B 各有自己的连通边；旋转中禁止所有行走，只有动画结束才提交新的桥朝向和开放边。
- 角色移动中不接受新目标、不排队；重置优先级最高，统一取消旧路径和动画回调。
- 只有实际停稳在 W/H 才能转桥。固定中央岛始终不转，角色在上面也不旋转。
- 角色脚底、朝向、步行节奏与脚影由同一路径进度驱动；接缝只改变深度，不能按真实长度原地踏步。
- 不可达操作使用可读反馈，不抛到控制台就不管，也不将角色自动传送到合法位置。
- 暂停后台动画时间；返回时不使用跨后台的大时间差更新位置。

### 4.3 视觉与性能边界

相机保持从 (14,14,14) 朝原点观察的方向，等比例扩展取景范围。旋转桥扫过的区域与入口/中央岛装饰保持净空，防止“角色被挡住但逻辑可走”。

使用基础材质、少量灯光和简单脚影，首版不依赖复杂后处理。渲染像素比上限建议 2；通过调整取景留白兼容 16:9 与 Mac 常见 16:10。

性能目标：本机 RTX 4080 在 1920×1080 下接近 60 FPS；用户 Mac 在实际记录的视口/像素比下目标同为 60 FPS。如不能达到，先给出帧时间与瓶颈，再调整阴影或像素比，不凭硬件型号声称通过。

## 5. 双平台离线包方案

### 5.1 共有结构与分平台入口

推荐共用同一份 `dist/`，随包提供固定版本的官方 Node 24 系列运行时和一个只用 Node 内置模块的小型静态服务。玩家不执行 npm 安装；npm、Vite 和 `node_modules/` 不进入玩家包。官方分发提供 Windows x64、macOS arm64 和 x64 运行时，打包时锁定具体版本及校验值。[Node 官方分发](https://nodejs.org/download/release/latest-v24.x/)

| 包 | 拟交付内容 | 启动入口 |
| --- | --- | --- |
| `jlbg-windows-x64.zip` | 游戏资源、Windows 运行时、本地服务、操作说明、依赖许可信息 | 双击 `Start.cmd`，调用包内运行时，打开默认浏览器 |
| `jlbg-macos-arm64` | 同一游戏资源、arm64 运行时、本地服务、操作说明、依赖许可信息 | 开发验证可先用 `Start.command`；面向玩家目标为带启动/退出界面的 `.app` 入口 |
| `jlbg-macos-x64` | 后续验证通过才追加 | 不用 arm64 包替代 Intel 原生验收 |

Node 仅提供本机文件服务，游戏仍在系统浏览器里显示；不为此引入 Electron。开发时继续使用本机 Vite，玩家包不启动 Vite 开发服务器。

Mac 的最终外壳封装是后续阶段的工作：先用脚本验证资源和运行时，再在 Mac 上制作并验证 .app 启动入口。当前不假设 Windows 可以完成 Mac 启动、执行权限和签名行为的最终测试。

### 5.2 启动与退出的可观察行为

1. 启动器根据自身位置定位游戏目录，支持路径含中文或空格，不依赖当前工作目录、全局 Node 或 PATH。
2. 服务只监听 `127.0.0.1`；默认尝试端口 `41731`，占用时请求系统分配空闲端口，绝不结束其他程序。
3. 监听成功后才打开浏览器。打开失败时显示实际本地地址和原因，用户可以复制地址；启动失败时不留下孤立服务。
4. 重复启动允许独立分配端口并显示各自控制窗口，不把其他实例误当本实例关闭；首关无跨会话存档，不承诺共享存档。
5. 启动控制界面提供明确退出方式。关闭游戏标签本身不等于关闭服务；Windows 控制入口退出、Mac .app 退出都须结束自身子进程并释放端口。
6. 启动器不联网下载组件、不自更新。服务只读游戏目录内的构建资源，正确提供 JS/CSS MIME 类型，不暴露上级路径。
7. 整包初次断网启动也必须可用。复制前预先运行过一次不能替代首次离线验收。

端口自动分配依据 Node 的标准监听行为实现，具体版本随运行时锁定。[Node 监听接口](https://nodejs.org/api/net.html#serverlistenport-host-backlog-callback)

### 5.3 Mac 下载后首次离线打开

真实下载包可能触发 macOS 对本地启动程序的安全检查；浏览器游戏不免除启动器这部分验证。受控试玩脚本不等于已经实现“任意玩家下载后双击即用”。

面向普通玩家的默认流程需要验证 .app 的签名、公证及离线票据处理。Apple 说明 ZIP 本身不能直接附带公证票据，需要处理其中支持的载体，如 .app。[Apple 公证工作流](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow)

本轮只记录交付要求，不使用开发者账号、不购买服务、不修改证书或系统安全设置。到玩家包阶段如需要用户账号或签名授权，应在具体构建方案可审查时说明并确认。不得把关闭 Gatekeeper 或删除隔离属性写成默认安装步骤。

若签名/公证条件尚未具备，可先交付明确标为“本地受控试玩”的 Mac 版本，但“默认设置下下载后首次离线双击运行”必须保持待验证，不能宣称最终目标完成。
